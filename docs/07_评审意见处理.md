## 结论一览

| # | 意见 | 是否成立 | 处理 |
|---|---|---|---|
| ① | 把"计划连接"当成"已共价连接" | **成立** | 拆出 `ligation_state`，`bonded` / `circle_closed` 只认事实 |
| ② | 没有确认 scaffold 实际可用区域 | **成立** | 新增阻塞参数 `scaffold.region`，必须显式写 `whole` 或 `[a,b)` |

## 复现记录（修复前）

```
① intended_ligation=全 True, 5′-P=no → circle_closed = True    ← 错
③ 输入 cut = [-628, 828, 100, 100] → 实际 [(100, 828)]         ← 静默归一
④ domain_order 切到 5p_scaffold_13 → validate_target_binding 报 28 条错
⑤ scaffold 长 100，[95,108) 与 [0,13) 实际重叠 8 nt → 未报 overlap
```

## 逐条修复

### ① 连接意图 ≠ 连接事实

`Nick` 新增 `ligation_state ∈ {none, planned, ligated}`：

- `intended_ligation` 仍表示**设计意图**，只映射成 `"planned"`；
- `Nick.bonded` 只在 `ligation_state == "ligated"` 时为真；
- `AssemblyPlan.circle_closed` 要求所有 nick 都是 `"ligated"`。

现在"全部计划连接 + 明确没有 5′-P"会得到 `circle_closed=False`，并且 `checks` 里带
`not_covalently_closed` 的提示。实验确认连上之后，才允许把状态写成 `ligated`。

### ② scaffold 有效区域必须显式给出

- 配置新增 `scaffold.region`：`"whole"` 或 `[start, end)`（文件坐标，`end < start` 表示跨原点）；
- 它是**阻塞项**（`null` 时不生成任何东西），"整段"也必须写 `"whole"`；
- 区域先按文件坐标切、再按 `strand` 定向；
- 报告新增 `scaffold_region`：模式、文件坐标范围、工作序列长度、以及**坐标映射说明**
  （staple 的 scaffold 坐标以工作序列 0 点为原点，换算回文件坐标要加 `file_coordinates[0]`）。

### ③ 切点严格校验

```python
切点必须是 int；0 < cut < L；不允许重复
```
`-628` / `828` / `[100, 100]` 现在都会抛 `ValueError` 并说明原因，不再取模或去重。

### ④ domain 顺序

- `validate_target_binding` 新增 `domain_order` 参数：`5p_target_26` 取前 26 nt，
  `5p_scaffold_13` 取**后** 26 nt；
- `run_validation` 从 `design_report.json` 里读实际的臂长与 `domain_order`，不再用默认值；
- 修正了生成器导出 domain 时的切片（原来反向模式下从第 26 位切，实际应从第 13 位切）。

### ⑤ 环状重叠

改为位置占用表：把每条 staple 的 13 nt 展开成 `(start + i) % L`，任何位置被两条 staple 占了就报
`scaffold_site_overlap`。跨原点的末段与首段自然会被发现（有正反两个用例守着）。

### ⑥ 逐条 nick 化学状态

- `build_nicks(..., nick_overrides={"N3": {...}})` 可按 nick 覆盖 5′-P、3′-OH、连接状态；
- `three_prime_hydroxyl` 默认值从 `"yes"` 改为 `"unknown"`（程序不知道就不写"是"）；
- 验证器新增交叉核对：nick 记录的 5′-P / 3′-OH 与上下游 oligo 声明的端基修饰不一致时报警。

### ⑦ 主流程缺接缝规则

`check_design` 新增两条检查：`nick_on_seam`（nick 不得压在 staple 臂接缝上）与
`oligo_spans_no_seam`（每条 oligo 至少跨过一个接缝）。这两条以前只在 `mapping.validate_plan`
里，主流程确实没跑。

## 仍然存在的问题（没有在这次修）

**两套结构逻辑并存**：`mapping.plan_assembly`（Toy 结构模型）与 `design.run_design`（真实生成器）
各自构造 staple、各自做检查。本次把接缝规则补进了主流程，但**没有合并这两条路径**。
合并需要把 `mapping` 降级为纯几何工具、把检查集中到一处，属于结构性重构，留到后续。

## 对评审中两处表述的澄清

1. **"未完成双解析器交叉验证"**：在本机是因为 Biopython 放在 `build/pylibs`（沙箱 pip 装不上），
   运行时要带 `PYTHONPATH`；代码路径本身两条都测过。干净环境下 `pip install -r requirements.txt` 即可。
2. **"177 个测试"**：评审只跑了 11 个不写文件的用例。现在全套是 **196 个**（含本次 19 个回归用例），
   `python -m unittest discover -s tests` 全绿。
